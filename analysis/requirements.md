## Правила

| ID | Правило |
|---|---|
| BR-01 | QR идентифицирует устройство, а не конкретную сессию |
| BR-02 | При создании сессии прежние активные сессии устройства деактивируются, создаётся pending-сессия |
| BR-03 | Для создания требуются deviceId, strength, непустой список ingredients |
| BR-04 | Крепость представлена пятью значениями интерфейса: light, below_medium, medium, above_medium, strong |
| BR-05 | Состав хранится снимком JSON; изменение справочника не должно изменять историю |
| BR-06 | Гостевой запрос отмечается флагом masterCalled или mixRequested |
| BR-07 | При открытии панели мастер снимает pending и/или masterCalled |
| BR-08 | Сохранение рецепта сопровождается снятием mixRequested |
| BR-09 | При изменении ингредиентов прежний рецепт сбрасывается в интерфейсе редактирования |
| BR-10 | При отсутствии активной сессии гостю возвращается пустое состояние |
| BR-11 | Мастерские поля требуют авторизации |
| BR-12 | Аналитика агрегируется по календарным границам МСК |

## Нефункциональные требования TO-BE

- Согласовать целевой p95 для загрузки гостевого экрана при заданной нагрузке.
- Определить SLA подтверждения запроса и восстановление состояния после обрыва связи.
- Обеспечить изоляцию гостевой информации от рабочих данных и ограничить избыточные запросы.
- Гарантировать единственную активную сессию на устройство при конкурентных операциях.
- Согласовать правила хранения истории и удаления меток.

Достигнутые SLA/SLO и нагрузочные характеристики неизвестны.
