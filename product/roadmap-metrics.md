# Roadmap и продуктовые метрики (TO-BE)

[К кейсу](../README.md)

## AS-IS

ScanEvent фиксирует обращения к поиску активной сессии по метке. Дашборд показывает суммы за день, неделю и месяц в московском времени; почасовой график включает 12–23 часы. Повторные обращения и программные обновления могут учитываться как сканирования. Это не уникальные гости, не число заказов и не конверсия.

## Предлагаемые события

| Событие | Атрибуты (без персональных данных) |
|---|---|
| guest_view | sessionId, deviceId, timestamp, источник |
| request_created | requestId, sessionId, type, timestamp |
| request_acknowledged | requestId, timestamp |
| recipe_delivered | requestId, timestamp |
| form_confirmed | sessionId, inputMode, timestamp, corrections |

## Метрики

| Метрика | Определение |
|---|---|
| QR adoption | Сессии с хотя бы одним guest_view / завершённые сессии с меткой |
| Request acknowledgement rate | Подтверждённые запросы / созданные запросы за зрелую когорту |
| Time to acknowledge | Медиана и p90 от создания запроса до подтверждения |
| Recipe fulfillment rate | Доставленные рецепты / запросы рецепта за зрелую когорту |
| AI-assisted form time | Медиана времени от начала заполнения до подтверждения, по способу ввода |
| AI correction rate | Формы с ручными правками / формы с AI-предложением |

Предлагаемая North Star: число обслуженных сессий с полезным гостевым взаимодействием за неделю (просмотр состава либо подтверждённый запрос). Проверить связь с пользой для гостя и нагрузкой мастера. Фактические значения отсутствуют.

## Приоритизация

| Приоритет | Работа | Критерий |
|---|---|---|
| P0 | Надёжность состояния сессии и доставки запросов | Приёмочные тесты пройдены |
| P1 | Инструментировать запрос и подтверждение | Измеряется сквозной цикл |
| P1 | Проверить UX гостя и мастера | Наблюдения, проблемные сценарии |
| P2 | Проверить пользу голосового ввода | Время заполнения и доля правок против ручного ввода |
| P2 | Проверить интерес к сохранению рецепта | Интервью и тест прототипа |

Гипотеза: голосовой ввод сокращает время создания сессии без роста ошибок. Сравнить одинаковые синтетические сценарии вручную и голосом, измерить время, исправления и ошибки состава; затем провести наблюдение в заведении. Не заявлять улучшение до измерения.
